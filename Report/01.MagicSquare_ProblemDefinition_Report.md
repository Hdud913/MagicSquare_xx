## 1. 문서 목적

솔루션(프로그램·UI) 가정 **이전**에, Mom Test로 검증한 **진짜 문제**와 MagicSquare **도메인 규칙**을 고정한다.

## 2. 도메인 정의

### 2.1 마방진 (4×4)

| 규칙 | 값 |
|------|-----|
| 격자 | 4×4 |
| 숫자 | 1~16, **중복 없음** (완성 시) |
| 빈칸 | `0` — **정확히 2개** (과제 전제) |
| 목표 합 | **34** |
| 검증 축 (**10선**) | 행 4 + 열 4 + 주대각선 1 + 부대각선 1 |

### 2.2 슬라이드 예시 격자

| | c1 | c2 | c3 | c4 |
|---|-----|-----|-----|-----|
| r1 | 16 | 3 | 2 | 13 |
| r2 | 5 | 10 | 11 | **?** |
| r3 | 9 | 6 | **?** | 12 |
| r4 | 4 | 15 | 14 | 1 |

과제: 빈칸 2곳 **위치** 특정 + 1~16으로 **완성**.

### 2.3 ECB 맥락 (전체 설계)

| 계층 | 구성 요소 | 역할 |
|------|-----------|------|
| **Entity** | `MagicSquare`, `Cell`, `SolveResult` | 격자·셀·풀이 결과 |
| **Control** | `SquareValidator`, `MissingFinder`, `Solver` | 검증, 빈칸 탐색, 완성 |
| **Boundary** | `GridUI`, `InputHandler`, `ResultDisplay` | 표시·입력·결과 |

**문제 정의 1차 범위:** `SquareValidator` 및 검증 루프 (Mom Test 우선순위).

## 3. Mom Test 결과

### 3.1 페르소나

**4×4 격자, 빈칸 2개(0), 1~16, 합 34를 맞추는 학습자.**

### 3.2 인터뷰 답변 (과거 사실)

> 지난 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 대각선 하나를 빼먹어서 20분 날렸다.

| 평가 | 판정 |
|------|------|
| 과거·구체·사실 | ✅ |
| 솔루션 섞임 | ✅ 없음 |
| 미래 가정 | ✅ 없음 |

**미답 추궁:** 대각선 누락을 **언제** 알았는지, 이후 **무엇을 다시 했는지**.

### 3.3 표면 문제 (잘못된 정의 — 구현 목표로 쓰지 않음)

- 「4×4 마방진 ECB 구조로 **프로그램(솔버·UI) 만든다**」
- 「빈칸 2개 찾아 채우는 **마방진 앱·과제**를 완성한다」

### 3.4 진짜 문제 (한 문장)

**지난 4×4 마방진 과제에서 빈칸 2개와 합 34를 맞추다 행·열·대각선을 모두 검증하지 못해 잘못 완료한 뒤 20분을 썼다.**

| 요소 | 내용 |
|------|------|
| 불편 | 대각선 검증 누락 → “맞았다” 착각 |
| 비용 | 20분 |
| 판정·재현 | 부분 검증(행·열)만으로 완료 처리 |

### 3.5 Mom Test 증거 3줄 (인용)

1. 「지난 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데」
2. 「대각선 하나를 빼먹어서」
3. 「20분 날렸다」

### 3.6 Mom Test 채점 요약 (8/10)

| 체크 | 결과 |
|------|------|
| 미래 가정 없음 | ✅ |
| 과거 행동·시간·실수 | ⚠️ 발견 시점·재시도 미기입 |
| 진짜 문제에 TDD/PyQt/Cursor 등 없음 | ✅ |
| 표면 / 진짜 분리 | ✅ |
| 도메인(4×4, 34, 빈칸 2, 10선) | ⚠️ 10선·34를 증거에 더 명시 가능 |

## 4. 문제 인식 (실패 조건)

Mom Test 증거와 1:1 연결.

| # | 실패 조건 | Control / Boundary | 증거 |
|---|-----------|-------------------|------|
| F1 | 10축 중 일부 합 ≠ 34인데 **완료** 처리 | `SquareValidator` | 대각선 빼먹음 |
| F2 | 빈칸 ≠ 2개 또는 위치 오류 | `MissingFinder` | 빈칸 2개 과제 |
| F3 | 1~16 중복·누락·0 잔존 (완성 시) | `Solver` / Rule | 마방진 완성 |
| F4 | 실패 시 **어느 축**이 틀렸는지 미제공 | `ResultDisplay` | 20분 재작업·재현 |

**핵심 통제점:** `SquareValidator` — 행·열·**양 대각선** 포함 **10선** 합 34, pass/fail + 실패 축.

## 5. 세션 3 — 주제·범위 (워크북 초안)

### 5.1 주제 (한 문장)

**4×4 마방진에서 행·열·양 대각선(10선)이 모두 합 34인지 판정하는 검증 규칙과 확인 루프를 만든다** — 잘못된 완료로 20분을 쓰는 일을 줄이기 위함.

### 5.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 위 페르소나 (학습자) |
| **Goal** | 10선 합 34 **일괄 판정**; fail 시 **깨진 축** 식별 |
| **Input** | 4×4 정수 격자 (`0` = 빈칸, 1~16) |
| **Output** | `pass` \| `fail` + fail 시 축 목록 (`row2`, `col3`, `diag_main` 등) |

### 5.3 성공 기준 (3)

| # | 기준 | 증거 |
|---|------|------|
| S1 | **10선** 합 34 검사 (대각선 2 포함) | 증거 1 |
| S2 | 대각선만 틀려도 **fail** (부분 통과 금지) | 증거 2 |
| S3 | fail 시 **실패 축** 출력 → 재작업·20분 낭비 감소 | 증거 3 |

### 5.4 이번에 하지 않을 것 (표면)

| 제외 | 이유 |
|------|------|
| 전체 Solver / 자동 완성 | 진짜 문제는 풀이 속도가 아닌 **검증 누락** |
| ECB 전체 UI·앱 | 1차는 Rule + Validator + Test Loop |
| 행·열만 검증 | F1·증거 2와 모순 |
| 「프로그램 만든다」를 목표 문장으로 사용 | Mom Test 표면 정의 |

### 5.5 8계층 — 세션 3 산출

| 계층 | 내용 |
|------|------|
| **Rule** | 4×4; 0 또는 1~16; 완성 시 0 없음·중복 없음; **10선 합 34** |
| **Command** | `validate(grid)`, `validate_axis(...)`, `report_failures(result)` |
| **(Skill)** | `SquareValidator` — 10선 검사·실패 축 식별 |
| **Test Loop** | 입력 → validate → pass 종료 / fail → 축 확인 → 수정 → 반복 |

**후속 세션:** Entity 상세, `MissingFinder`, `Solver`, Boundary UI.
