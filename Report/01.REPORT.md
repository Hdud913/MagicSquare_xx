## 1. 개요

4×4 마방진(행·열·대각선 합 34)에서 **빈칸 2개 위치를 찾고 1~16 숫자를 채우는** 과제를 ECB(Entity–Control–Boundary) 패턴으로 설계·구현하는 프로젝트이다.

STEP 1에서는 Rob Fitzpatrick **Mom Test** 방식으로, 솔루션(프로그램·앱) 가정 전에 **과거 사실·비용·행동**을 수집해 문제를 정의한다.

| Mom Test 단계 | 상태 |
|---------------|------|
| 워크북 초안 | 제출됨 → **과거 사실 1건** 보완 |
| 인터뷰 진행 | 오프닝 질문 1회 + **과거 사실 답변 1건** |
| 응답자 과거 사실 답변 | ✅ 있음 (지난 과제, 20분 비용) |
| 인터뷰 종료·문제 정리 | **증거 인용 3줄** 확정 (§4.3) |

## 2. 프로젝트 정의 (슬라이드 요약)

### 2.1 마방진 과제

- **크기:** 4×4
- **목표 합:** 34 (행·열·대각선 동일)
- **과제:** 빈칸(물음표) 2곳의 **위치**를 찾고, 1~16 중 올바른 숫자 배치

**예시 격자 (슬라이드):**

| | c1 | c2 | c3 | c4 |
|---|-----|-----|-----|-----|
| r1 | 16 | 3 | 2 | 13 |
| r2 | 5 | 10 | 11 | **?** |
| r3 | 9 | 6 | **?** | 12 |
| r4 | 4 | 15 | 14 | 1 |

### 2.2 ECB 분류 (설계 예정)

| 계층 | 구성 요소 | 역할 |
|------|-----------|------|
| **Entity** | `MagicSquare`, `Cell`, `SolveResult` | 격자·셀·풀이 결과 상태 |
| **Control** | `SquareValidator`, `MissingFinder`, `Solver` | 합 검증, 빈칸 탐색, 완성 알고리즘 |
| **Boundary** | `GridUI`, `InputHandler`, `ResultDisplay` | 격자 표시, 입력, 결과 출력 |

### 2.3 실습 목표

1. ECB 분류 완료
2. **문제 인식(실패 조건)** 최소 3가지 도출

## 3. Mom Test 워크북

### 3.1 워크북 (현재)

| 항목 | 내용 |
|------|------|
| **페르소나** | 지난 마방진 과제를 수행한 **학습자**(4×4, 빈칸 2개·합 34 맞추기 경험) |
| **인터뷰 답변 (과거 사실)** | 지난 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데, **대각선 하나를 검증에서 빼먹어서** 잘못된 상태로 **20분**을 썼다. |
| **표면 문제 (금지)** | 「4×4 마방진 ECB 구조로 **프로그램(솔버·UI) 만든다**」 / 「빈칸 2개 찾아 채우는 **마방진 앱·과제**를 완성한다」 |
| **진짜 문제 (한 문장)** | §4.2 참고 |

### 3.2 인터뷰 규칙 (적용)

| 검증 대상 | 비검증 (금지) |
|-----------|----------------|
| 이미 한 행동, 시간·비용, 마지막 시도 | “ECB 프로그램 만들면 좋겠다” 등 솔루션 |
| 과거·구체·사실 | “~하면 쓸 것 같다” 등 미래 의견 |

### 3.3 진행한 질문 (오프닝)

> 가장 최근에 4×4 마방진(또는 비슷한 숫자 격자 퍼즐)에서 “빈칸/물음표”를 채우거나 맞추려고 시도한 때가 언제였나요? 그날 정확히 무엇을 했는지 순서대로 말해 주세요.

**응답 (과거 사실):**

> 지난 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데 대각선 하나를 빼먹어서 20분 날렸다.

| Mom Test 평가 | 판정 |
|---------------|------|
| 사실 / 과거 / 구체 | ✅ (지난 과제, 빈칸 2, 행·열·대각선, 20분) |
| 솔루션 섞임 | ✅ 없음 |

**추궁 질문 (미답):** 대각선 누락을 **언제** 알았는지, 그때 **무엇을 다시 했는지**.

## 4. 인터뷰 종료 시 문제 정리

과거 사실 1건을 반영해 **진짜 문제·증거**를 확정함.

### 4.1 표면 문제 (잘못된 정의)

- 「4×4 마방진 ECB 구조로 **프로그램(솔버·UI) 만든다**」
- 「빈칸 2개 찾아 채우는 **마방진 앱·과제**를 완성한다」

→ 솔루션·기능이 문제 정의에 섞인 형태. Mom Test에서는 **기록만** 하고 진짜 문제로 쓰지 않음.

### 4.2 진짜 문제 (한 문장)

지난 과제처럼 4×4 마방진에서 빈칸·합을 맞출 때 **행·열·대각선을 모두 같은 기준으로 검증하지 못해** 잘못된 완료로 **20분**을 썼다.

| 구성 요소 | 내용 |
|-----------|------|
| **불편** | 대각선 1개를 검증에서 빼먹어 “맞췄다”고 착각 |
| **비용** | 20분 |
| **판정·재현** | 행·열만 보면 통과, 대각선 기준 누락 → 완료 판정 오류 |

### 4.3 Mom Test 증거 3줄 (인용)

| # | 인용 |
|---|------|
| 1 | 「지난 과제에서 빈칸 2개 넣고 행·열·대각선 합 맞췄는데」 |
| 2 | 「대각선 하나를 빼먹어서」 |
| 3 | 「20분 날렸다」 |

## 6. 문제 인식(실패 조건) — ECB 연계

Mom Test 진짜 문제에 맞춘 실패 조건 (최소 3개).

| # | 실패 조건 | 관련 Control/Boundary | Mom Test 근거 |
|---|-----------|------------------------|---------------|
| 1 | **대각선(또는 행·열) 중 일부 합**이 34가 아닌데도 “완료”로 처리 | `SquareValidator` | 대각선 하나 검증 누락 → 20분 낭비 |
| 2 | 빈칸이 2개가 아니거나 위치를 잘못 특정 | `MissingFinder` | 빈칸 2개 과제 전제 |
| 3 | 1~16 중복·누락 없이 배치하지 못함 | `Solver` | 마방진 완성 조건 |
| 4 | 검증 실패 시 **어떤 축(행/열/대각)** 이 틀렸는지 알려주지 않음 | `ResultDisplay` | 판정·재현 어려움 (추가 인터뷰로 보강 가능) |

**`SquareValidator` 요구사항 (인터뷰에서 도출):** 행·열·**양 대각선** 모두 합 34 검사 후에만 완료 허용.
